# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`palaver` — a node-graph dialog editor in the spirit of articy:draft: branching dialogue graphs of speaker/text nodes connected by labelled choice edges.

Every section above **Out of scope** describes code that exists. There is no roadmap: the editor is feature-complete against its own scope, and **Out of scope** at the bottom lists what was deliberately not built at all.

## Stack

- GUI: **GPUI** (`gpui` 0.2.2), the framework Zed is built on. Its API still moves between releases — the version is pinned, and when an API doesn't match the docs, read the source in `~/.cargo/registry/src/*/gpui-*/` rather than guessing.
- On Linux GPUI renders through Vulkan/Blade and needs X11/Wayland + Vulkan dev packages present; a build failure in `blade-*` or `gpui` almost always means a missing system lib, not a code bug.

## Commands

The tree is clean under both `cargo fmt --check` and clippy at `-D warnings`; keep it that way — **with and without `--features automation`**, since clippy only sees the feature-gated module when it is on.

`python3 -I tools/shots.py docs/shots/<pass>` screenshots the editor in a fixed list of states (the `SHOTS` table in the script): it builds with `--features automation`, launches the editor against a private `TMPDIR`, drives it over the automation socket and captures each state with Spectacle. Same states every run, so two runs either side of a change are a before/after pair; `--only hub,edge` reruns a subset. Spectacle captures the *active* window, so the desktop has to be left alone while it runs, and a capture of the wrong window is renamed `*.wrong-window.png` rather than kept. GUI changes are verified with this, not with `cargo test`.

## Layout

Four files, no `lib.rs`, plus one behind a feature:

- `src/doc.rs` — the document model. `Doc` plus geometry constants (`NODE_W/H`, `PORT_R`), hit-testing, undo and JSON IO. **Imports no `gpui`** and must stay that way; it is the only testable layer (unit tests at the bottom of the file). It also holds `View`, the canvas pan/zoom transform — not document state, and never serialized, but pure arithmetic that belongs where it can be tested.
- `src/main.rs` — `Editor`, the single `Render` view: menu bar, then a row of variables pane, canvas pane and inspector, the status bar under all three, and the overlays (find, problems, shortcuts) that are in the tree only while open — plus all mouse/key handling.
- `src/text_input.rs` — a single-line `TextInput`, **vendored from gpui 0.2.2's `examples/input.rs`**; the header comment lists the local deltas. Treat it as third-party: on a gpui upgrade, re-vendor and re-apply the deltas rather than hand-patching. It holds the crate's only hand-written `impl Element` (`TextElement`). `text_input::bind_keys(cx)` must be called at startup or the fields ignore every key.
- `src/theme.rs` — the design tokens: every colour, font and text size the view draws with, **named for what it means, not what it looks like**. Colours are an elevation ladder of surfaces (`CANVAS` → `PANE` → `RAISED` → `HOVER` → `PRESSED`), three text tiers measured against WCAG AA rather than eyeballed, and one hue per meaning — the file exists because amber once meant an ending, a condition, a note *and* a number. Text styles are roles on the `Typography` trait (`type_title`, `type_label`, `type_hint`, `type_section`), which own size, weight and colour together. **`one_line()` is how text ends in `…`, and `truncate()` is banned for it:** `truncate()` sets no-wrap, gpui only truncates text it is first measured at a definite width, a flex item is first probed at its full content width, and that answer is cached — so the later, correctly sized pass never truncates and the box just clips mid-letter. A one-line *clamp* keeps wrapping on, so it re-measures. Two corollaries that cost a debugging session: the clamp has to sit on the element whose *direct child is the text*, not on a flex row of bare text children (put the label in its own `flex_1` + `min_w(0)` box), and a shrink-to-fit box such as the edge-label pill needs a **definite width** or gpui wraps a line wider than the box and clips both sides. **No hex literal belongs outside this file**; the one exception is `CAST_COLORS` in `main.rs`, which is document data written into `.dln` files, not theme. A new meaning gets a new token even when it reuses an existing shade (`TRUE = SUCCESS`), so the call site names the reason.
- `src/automation.rs` — **development tooling, compiled only with `--features automation`**: a Unix socket, one command per line, that puts the running editor into a state for `tools/shots.py` to screenshot. Every command goes through a handler the UI already uses (a `MENUS` fn pointer, `select`, `jump_to`, `switch_pane`, `show_flow`, `play_advance`, a field's `set_content`) and never touches `Doc` directly, so a script can reach no state a person could not; a new command follows the same rule, and a handler that only exists as an inline click closure gets lifted into a method first, as `switch_pane` and `show_flow` were. The socket and the crash copy both live in `temp_dir()`, and `replace_doc` deletes the crash copy, so **isolation is the launcher's job**: the script sets `TMPDIR` to a private directory, or an automated `open` would delete a real crash copy. The module turns autosave off for the same reason.

## How the canvas is actually drawn

Hybrid, deliberately:

- Node boxes, port dots and edge labels are **absolutely-positioned `div`s** built in `Editor::canvas_pane`. Follow this when adding chrome — do not port them to a custom element.
- Only the edge lines and arrowheads go through gpui's `canvas()` helper + `PathBuilder`, because there is no div-based way to draw a diagonal line.
- Hit-testing is **not** GPUI's; it is arithmetic in `doc.rs` (`hit_test`, `port_hit_test`, `edge_at`, `nodes_in_rect`) run from `Editor::on_mouse_down`. Ports overlap node boxes, so `port_hit_test` must be checked first. `hit_test` iterates in reverse so the topmost (last-painted) node wins.

### The mouse map

`on_mouse_down` is an ordered if-chain and the order *is* the specification; adding a gesture means picking its rung. Alt is checked before any hit test, so Alt+left pans over anything. Then: out-port → edge drag; node + shift → toggle it in the set, no drag; node already selected → keep the set and drag the group; node → select just it and drag; edge → select it; empty + double-click → create; empty → marquee.

**Middle-drag pans**, via `on_pan_down`, which the Alt+left branch also calls — the two gestures share one function so they cannot drift apart. `on_mouse_move` is button-agnostic, so panning needed nothing there, but every button that can start a drag must register `on_mouse_up` *and* `on_mouse_up_out`.

A plain click on empty canvas is a zero-size marquee that touches nothing, so clearing the selection falls out of the marquee commit in `on_mouse_up` rather than being its own branch.

### Coordinate spaces (the most common source of bugs)

Three of them:

1. **Window** — what mouse events carry.
2. **Canvas pane** — window minus `MENU_H` *and* minus `VARS_W`, since the pane sits under the menu bar and to the right of the variables pane. With `SIDEBAR_W`, those three constants are what bound the pane. Any new chrome to the left of or above the canvas has to be subtracted in `Editor::window_pos` too, or every hit test in the editor is wrong by its width — this is the single most breakable thing in the file. The status bar makes the pane shorter at the *bottom* by `STATUS_H`, and hit tests measure from the top-left, so — unlike the other three — it is not subtracted in `window_pos`; only `pane_center`, the one place the pane's height is read, has to know.
3. **Document** — `screen = doc * zoom + pan`. Everything in `doc.rs` is in this space.

`View::to_doc`/`to_screen` own step 3; `Editor::window_pos` owns step 2, and `doc_pos`/`screen_pos` compose the two. Go through those helpers, never the raw arithmetic. Separately, inside the `canvas()` paint closure coordinates are window-absolute, so `bounds.origin` is added back.

`pan` is in **screen** pixels, which is why `Drag::Pan` is the same arithmetic at every zoom. Lengths that start in document units (`NODE_W`, `PORT_R`, label widths, font sizes) need `View::scale`. Hit tolerances (`PORT_R`, `EDGE_HIT_TOL`) are deliberately *not* scaled — they live in document space, so targets get smaller on screen as you zoom out.

## Invariants

- **Checkpoint before you mutate.** `Doc` never checkpoints itself — the view calls `doc.checkpoint()` *before* each mutation. It pushes a full snapshot (50 deep) *and* sets the dirty flag; it is the single choke point for both, and `dirty` is only cleared in `save()`. A mutation that skips it is both un-undoable and silently unsaved. `Snapshot` is every serialized field of `Doc`, so a new one has to join it or a whole class of edit quietly stops being undoable; `undo_restores_a_deleted_variable` is the test that catches the omission. `undo()` and `redo()` also set dirty — stepping through history counts as an edit.
- **`checkpoint()` clears the redo stack**, since a fresh edit branches history. `undo`/`redo` are symmetric: pop one stack, push the current snapshot onto the other. Only `undo` is capped at `UNDO_DEPTH`; the redo stack needs no cap of its own because it can only ever hold snapshots `undo` popped.
- **Checkpoints are placed to avoid empty undo steps.** Typing coalesces: `Editor::checkpoint_once` + the `text_dirty` flag give one checkpoint per editing session, and `text_dirty` resets in `load_fields` when the selection changes. Node drag checkpoints on the first `MouseMove`, not on mouse-down, so a plain click leaves no history entry.
- **`Selection` is `None | Nodes(Vec<u32>) | Edge(usize)`** — plural for nodes, singular for edges. `Selection::Edge(usize)` is a bare index into `doc.edges`, invalidated by any edge removal; the mitigation is convention: every structural change calls `select(Selection::None, cx)`, and `after_history` re-validates the node set against the document and drops anything else. Node ids survive a history step, so a node set does not need the same treatment — only the ids that vanished are filtered out.
- **`Selection::only_node()` is the gate on every single-node path** — `load_fields`, `sync_fields`, `on_branch`. A multi-selection returns `None` there, so it has no inspector fields to write and cannot half-edit a group. New per-node commands go through it too, not through `nodes()[0]`.
- **A group drag anchors the grabbed node and moves the rest by its delta** (`Drag::Node` in `on_mouse_move`), rather than storing a per-node offset. That way the node under the cursor never drifts, and the maths is the same for one node as for twenty.
- **A start is relative to the selection, not a property of the document.** `Doc::start_of(id)` walks incoming edges back to a node nothing links to, so a document holds as many independent conversations as the author draws and F5 plays whichever one the selection is standing in (Shift+F5 starts at the selected node itself). This is why `Problem::ManyStarts` was deleted: several roots is now the intended shape. `NoStart` stays, since a document where nothing can begin is still broken. `start_of` guards against cycles with a visited set and returns the node it started from when there is no top to find.
- **Play state is one `Option<Vec<u32>>`** on `Editor` — the path walked so far, current node last, which is all Back (`pop`) and Restart (`truncate(1)`) need. While it is `Some`, `play_panel` *replaces* the selection arms in `inspector` so the sidebar is never an editor and a player at once, and `replace_doc` clears it because node ids belong to the document that left. Play follows the canvas with `Editor::show` (centre only) rather than `jump_to`, deliberately: advancing must not rewrite the selection play was started from. The panel guards on `doc.node(current)`, since the node can be deleted from the canvas mid-play.
- **A `Jump`'s target is an ordinary `Edge`.** The whole trick of it is that a jump introduces no second kind of link: `choices`, `problems` reachability, `start_of` and `nodes_in_rect` need no jump awareness because the edge is real, and the target is authored by dragging from the out-port like any other. The kind only changes how that edge is *drawn* — `edge_lines` and `edge_labels` both skip an edge leaving a jump (via `Doc::is_jump`, shared so the two cannot drift), and `node_box` names the target instead. A jump has exactly one target: `add_edge` refuses a second, and `Doc::set_kind` drops all but the first outgoing edge when converting a node to one, because an edge that is neither drawn nor reachable would be a lie about the graph.
- **Kinds change what a node draws, never how big it is.** Hit-testing is arithmetic over `NODE_W`/`NODE_H` in `doc.rs`, so a hub drawn smaller than it is clicked would put the two out of step. Every kind keeps the same footprint.
- **`end: bool` stays orthogonal to `NodeKind`, deliberately.** An ending has text — "Farewell, traveller." is a `Speech` node that happens to terminate — so folding `End` into the enum would make "is an ending" and "is dialogue" mutually exclusive. `Problem::Empty` means "holding none of whatever this kind exists to hold" — no dialogue on a `Speech`, no writes on an `Instruction` — so `Hub` and `Jump` are exempt from it for the same reason `end` exempts a node from `DeadEnd`: neither holds anything to begin with. **Only a `Speech` node has a speaker.** A hub's `text` is an optional label for it ("Anything else?"), a jump and an instruction use neither field, and `Node::speaker` never means anything but who is talking — which is what keeps **entities** from having to special-case a kind that nobody speaks at.
- **A `Node::alias` is the only stable handle the format offers the outside world.** `Node::id` is a random `u64` minted per node — unique and stable, but meaningless to a human and unwritable by hand — and a start is derived by `Doc::start_of` rather than stored, so neither is something an author can point a game build at. That sets the alias's two rules: **never auto-generated, never auto-renamed**, because a handle the editor changes is not a handle. Empty is the ordinary state — the field is reachable from every node so that *any* node can be named, not so that every node must be, and a blank alias is never a `Problem`. Orthogonal to `NodeKind` like `end` is, so the inspector field sits outside every kind guard: entering a conversation at a hub or a condition is a legitimate thing for a game to want. Conflicts are caught after the fact, not refused at entry the way a duplicate variable name is — `sync_fields` runs on every keystroke, so typing toward `intro_two` transiently reads `intro` and a gate would refuse the author mid-word. `Problem::DuplicateAlias` is therefore an `Error` raised on *both* offending nodes, and only between two **non-empty** aliases that match: without that skip every un-aliased node in the document would collide with every other.
- **Logic is graph structure, never a node property.** This is articy's model and the reason `NodeKind` keeps growing instead of `Node` growing fields: an `Instruction` is a node you can see, select, move and search, not a hidden panel on a line of dialogue. It is also what keeps the crate clear of **Templates** (see *Out of scope*) — a `Node::effects` bag readable on every kind would be a miniature of exactly that. `effects` is therefore the *content* of an `Instruction`, the way `speaker` is only ever a `Speech` node's: `vars_along` reads effects only from an `Instruction`, and `Doc::set_kind` clears them when converting a node away from one, so the field cannot quietly become a property bag.
- **`Doc::pauses_play` is the one definition of a node the player sees** (`Speech | Hub`; a missing node counts as visible, so a broken graph halts rather than walking off the end). The walk and the panel that renders its result both go through it, so they cannot disagree about which nodes are authoring plumbing. A hub is a branch point, so `play_panel` shows its label above its choices, or nothing at all when it has none — its one hub arm, since a blank hub is complete (`Problem::Empty` exempts it) and must not read as an unwritten line. The walk normally lands on a node this is true of — when it does not, it ran out of graph (a condition with that pin unwired, a jump pointing at nothing), and `play_panel` must say so rather than render a plumbing node as a blank line of dialogue.
- **A condition's true/false pins are a `bool` on the `Edge`, not a second out-port.** `out_port`, `port_hit_test` and the whole mouse map therefore know nothing about the kind, and a branch is authored by dragging from the same single port. `add_edge` gives the *first* edge out of a condition the true branch, since the happy path is what gets drawn first. `Edge::branch` is meaningless from any other kind and left `false` there. The branch is shown two ways so it is never guessed at: the line is drawn in `TRUE_COLOR`/`FALSE_COLOR`, and `edge_labels` writes `true`/`false` in the label slot — which on a condition would otherwise hold text the player can never read, so the edge inspector swaps the Choice field for the branch toggle too.
- **`walk_on` is the only place a condition is ever evaluated**, and `Doc::choices` is never filtered — the editor and the player see the same graph, and the canvas never hides an edge. That is the payoff of logic-as-nodes over guarding edges, which was considered and rejected. The walk recomputes `vars_along(path)` at each condition it meets rather than carrying a `VarState`, which keeps the path the single copy of the play state.
- **`effects` and `conditions` are separate fields with a shared editor.** `Effect { var, value, op }` and `Condition { var, want, op }` are structurally parallel — though their ops are not the same enum, `SetOp::Set | Add` against `Cmp::Eq | Ne | Lt | Le | Gt | Ge`, which is the second reason not to merge them — and merging them would save a struct — but checks living in a field called `effects` is the `speaker`-as-hub-name mistake again. The duplication that actually mattered was the widget, so `var_rows` takes a `VarRow::Sets | VarRow::Checks` and both kinds share it.
- **The play path holds every node visited, including the ones walked through.** `Doc::start_walk`/`advance`/`step_back` do the walking, and they replaced `resolve_jump` rather than sitting beside it — it was already "walk through what the player never sees", and `Instruction` is just the second such kind. Keeping the invisible nodes in the path is what lets `Doc::vars_along` recompute the variables *from the path alone*: there is no second copy of the state, so Back cannot rewind the node without rewinding the flags. `step_back` searches by position, not by id, because a conversation that returns to a node it has already played would otherwise jump to the wrong occurrence of it. Restart re-walks from `path[0]` rather than truncating, so a conversation opening on an instruction runs it again. The walk guards against a cycle with a visited set, like `start_of`.
- **A once-only choice is spent by reading the path, not by marking the edge.** `Edge::once` is authoring intent — a `#[serde(default)]` bool beside `branch`, so an older `.dln` loads unchanged — and `Doc::spent(path, from, to)` is the whole of the runtime, a `windows(2)` scan for that traversal. Nothing is stored: **the path stays the single copy of the play state**, so Back unspends a choice along with the flags the run set, for the same reason `vars_along` cannot drift. It is keyed on the **pair, not the target**, which is exactly where a visit count on the node would have been wrong — two once-only choices landing on one node would spend each other — and `spent_counts_the_pair_not_the_node` is the test that says so. This is **not** a break of **`Doc::choices` is never filtered**: the canvas draws every edge, and `play_panel` greys a spent one out — the same place the player already diverges from the canvas by walking through nodes it does not show, and the reason "End of conversation." now fires when every choice is spent rather than when there are none. `walk_on` knows nothing about it, so the inspector only offers the toggle where `Doc::pauses_play`: out of an instruction or a jump the walk has to take the edge it finds, and a flag there would be a promise nothing keeps. Drawn as well as toggled, like a condition's branch — `edge_labels` prefixes `(once)` — in front of the label, since the slot is a fixed width and a long choice is already truncated, so a marker on the end is one you cannot see.

- **A field the current kind does not show is ignored, never erased.** `Doc::set_kind` cuts *edges and logic* — a note's edges, a jump's extra targets, effects off a non-instruction, checks off a non-condition — because keeping them would be a lie the graph tells. It keeps `text`, `speaker` and `end`, so Speech → Hub → Speech loses nothing; the price is that every reader asks the kind first, through `Node::is_ending`, `Node::player_text`, `Node::player_speaker` and `Doc::is_once`. Each exists because the raw field acted while hidden: a stale `end` silenced `DeadEnd` on a hub and drew its border, a stale `once` drew `(once)` out of an instruction with no toggle to clear it, a hub showed the speaker of the line it used to be, and an instruction's leftover line went out to translators. A new hidden-by-kind field gets a reader like these, not a clearing line in `set_kind`.
- **`Problem` carries no message text.** `Doc::problems` returns an enum; the wording lives in `problem_text` in `main.rs`, which keeps view strings out of the model and lets the tests assert on variants instead of phrasing. Its `Severity` split is load-bearing, not decoration: a leaf node is an ordinary way for a conversation to end, so only a broken document (`DanglingEdge`, `NoStart`) is an `Error`. Anything new that would fire on a healthy graph is a `Warning`. `Node::end` is the opt-out: a node marked as an ending is skipped by the `DeadEnd` rule, so the list only names leaves the author has not vouched for. Keeping the wording in the view also means a variant can read differently per node kind without the model growing a variant for it — `DeadEnd` on a jump is worded "Jump with no target".
- **The four inspector inputs are observed as a group; `search_input`, `var_input` and `value_input` are not.** The `sync_fields` loop in `Editor::new` exists to write field content *into* the selected node — a search query, a not-yet-declared variable name and a half-typed number are not that node's content, so they share a second observer that only calls `cx.notify()`. `value_input` is the crate's one number editor, shared by the variables pane and the inspector's Sets/Checks rows so there is never a second half-typed number about; `Editor::editing` says which value it is aimed at, is committed by a `✓` click (nothing in the crate binds enter), refuses a number that will not parse by leaving the field alone, and is filtered against the document at render the way `renaming` is. Adding a non-document field to the first loop would write it into the selected node; `alias_input` is in it precisely because an alias *is* node content.
- **A variable is keyed by its name, not by an id** — as a `Character` is, and unlike a `Node`. The name is what a `.dln` diff and a merge stay readable through, and there are few enough variables that `add_variable` can enforce uniqueness outright. The payoff is that a rename *is* a find-and-replace: `rename_variable` rewrites the declaration, every effect and every check, and there is nowhere else a reference can hide — which makes it, with `remove_variable`, the second function a third name-storing field would have to join. `variable_name_free` exists as a separate public check so the view can refuse an add *before* it checkpoints — a rejected add must not leave an empty undo step, and `checkpoint` also sets `dirty`. **One `.dln` is the project**, so global means document-global: `variables` is a field of `Doc`, declared from exactly one place (the `+` in `vars_pane`), and nothing else in the crate may mint one. `vars_pane` has one text field and two jobs — `Editor::renaming` is which — so a rename needed no fourth `TextInput` to keep out of the `sync_fields` observer group; a stale `renaming` is filtered at render against the document rather than cleared at every site that could invalidate it. `remove_variable` cascades to every effect naming the flag and returns the count, because an effect writing an undeclared variable has no meaning; it is one checkpoint, so one undo brings the variable and all of its effects back together. `Problem::UnknownVar` is an `Error` for the files that got there anyway — hand-edited or hand-merged — which is the same category `DanglingEdge` exists for.
- **A variable's type is which variant its `default` holds** — `Value::Bool | Value::Int`, with no separate type field that could fall out of step with the value. That makes a type change a find-and-replace exactly as a rename is: `retype_variable` converts the default and every effect and check naming it (`false`/`true` ↔ `0`/non-zero), and it is the **third** function a new variable-naming field would have to join, after `rename_variable` and `remove_variable`. It clamps operators as well as values, since `gold > 5` means nothing once `gold` is a flag. `Value`'s `PartialOrd` is hand-written and deliberately partial: a derived one orders by *variant*, making `Bool(true) < Int(0)`, so a comparison across types would get a wrong answer instead of none. `None` is what makes `Condition::holds` false on a mistyped check — the same answer an undeclared variable gets, and `Problem::TypeMismatch` is what says so out loud, an `Error` in the `UnknownVar` category of things only a hand-edit or a merge can produce. `Add` is the same story in `apply`: adding to a flag leaves the slot alone rather than inventing a value, and `saturating_add` keeps a big number from panicking a debug build.
- **The variables list is its own pane on the left, not part of the right sidebar.** The sidebar is the *inspector* — everything in it is scoped to the selection, and play replaces it wholesale. Variables belong to the whole document, so they get their own pane, stay up during play showing live values, and go read-only while it runs. `vars_pane` is also the only place in the crate that may declare a variable — or a character, or a flow.

- **A `Character` is keyed by its name, which is what made the cast cost no migration.** `Node::speaker` already held the name, so declaring a cast added a `characters` vec to `Doc` and *nothing* to `Node`: no id space, no optional field, no fallback for un-migrated files, and a `.dln` written before the feature loads with an empty cast and looks exactly as it did. The id space the roadmap sketched was dropped for that reason; only a second character wanting the same display name would force ids back. The name being the key makes `rename_character` the **second** find-and-replace in the crate after `rename_variable` — it rewrites the record and `Node::speaker` on every node that says it — so any third name-storing field has to join both. `character_name_free` is the pre-checkpoint check `variable_name_free` is, for the same empty-undo-step reason. But `remove_character` deliberately does **not** cascade the way `remove_variable` does: an effect naming an undeclared variable means nothing, while "Innkeeper" still speaks the line whether or not anybody declared them, so removing a character only *undeclares* it and `Problem::UnknownSpeaker` — a `Warning`, not an `Error` — is what says so. Only `NodeKind::Speech` is checked and blank speakers are skipped, exactly as `DuplicateAlias` skips blank aliases. The Speaker inspector field stays a text field rather than a picker, for the mid-word reason the alias rules already record; the colour is only ever drawn in the two places a speaker is (`node_box` and `play_panel`), both through `speaker_color`, which falls back to today's colour.

- **The left pane is three tabs over one list container and one text field.** `Editor::pane` (`Variables | Cast | Flows`) and `Editor::renaming` (`Item | Set`) together say which of `var_input`'s four jobs it is doing, and switching tabs clears the rename so a field aimed at the list you just left cannot rename the wrong thing. A *third* pane was rejected rather than designed: `Editor::window_pos` is the one place a new pane breaks every hit test in the editor, and a tab touches none of it. `CAST_COLORS` lives in `main.rs` for the reason `problem_text` does — the model stores the colour, the view chooses it, and the swatch cycles the palette because the crate has no colour-picker widget and every other choice in it cycles too.
- **A variable set is a naming convention, not schema.** `doc::split_set` splits a name on its first `.` and `vars_pane` renders a header per group, showing the rest of the name under it — but the whole dotted name is still the key, so uniqueness stays global, a rename is still a find-and-replace over one string, and a `.dln` is byte-identical to what it was before groups existed. That is the entire cost of the feature: display. A document with nothing dotted must look exactly as it did, which is why the `(ungrouped)` header only appears once some *other* variable has a set. The list itself scrolls (`overflow_y_scroll` on an inner `#var-list`, not on the pane, so the heading and the declare field stay pinned), so unlike its sibling panels it has no row cap — headers were about to make one bite twice as fast.

  The **affordances** were built on that convention rather than replacing it, and the roadmap's schema half was dropped for cause: per-set uniqueness buys nothing, since global uniqueness over a *dotted* name already is per-set uniqueness, and a `set` field on `Variable` would leave `Effect::var` and `Condition::var` joined — two sources of truth that can disagree — or change the file format and rewrite all three variable find-and-replace fns. So `join_set` is `split_set`'s other half, and the two are the whole model: the picker holds the set, the declare field holds the rest, and the view never learns the rule is a dot. `set_picker` is chips like `kind_picker` rather than a dropdown (there is no dropdown in the crate) and has **no "new set" chip on purpose** — a set is still made by typing the dot once, and the picker is autocomplete for the sets that exist, which is the whole of the typo problem. Because a variable rename splits into the picker and the field the same way, clicking another chip mid-rename *moves* the variable between sets, for free. `Doc::rename_set` is the **fourth find-and-replace** after `rename_variable`, `rename_character` and `rename_flow`; it refuses rather than merges when a resulting name would collide, and `set_name_free` is its pre-checkpoint guard, refusing a dot because a set is everything *before* the first one. `Editor::renaming` therefore became `Option<Rename>` (`Item | Set`): `Editor::pane` says which *list* an `Item` is in, and the one thing a pane cannot say apart is a variable's name from its set's, inside the same tab.
- **A flow is a named canvas, not a nested graph.** The roadmap sketched flow fragments as a tree of `Doc`s and priced that at ids, the `Selection` enum, per-fragment `View` state and the file format; none of it was paid. `Node::flow` says which canvas draws a node and `Doc::flows` holds the declared ones — two `#[serde(default)]` fields, so a `.dln` written before flows existed loads with every node in the unnamed main flow (`""`) and looks exactly as it did, the same no-migration trick keying a `Character` on `Node::speaker` played. The node list stays **flat and globally id'd**, which is what keeps `fresh_id`, `Selection`, `start_of`, `choices`, `start_walk`, `advance` and `vars_along` from ever learning the word: F5 plays a conversation across as many canvases as it is drawn on. The whole feature is `Doc::nodes_in` — one filter — plus a tab, and it is a *third* tab rather than a third pane precisely because `Editor::window_pos` is the one place a new pane breaks every hit test.

  Two consequences to keep. **Only the current canvas is drawn, so only it may be clicked**: `hit_test`, `port_hit_test`, `nodes_in_rect` and `edge_at` take the flow, which is why a node on another flow at the same coordinates is not reachable through this one. **An edge belongs to the canvas both its ends stand on** — `edge_at` and the two drawing fns (`edge_lines`, `edge_labels`) share that test so a line is never hit where it is not drawn, and crossing between flows is [`NodeKind::Jump`]'s job: its edge is already the one the canvas does not draw and its box already names the target instead. An ordinary edge that crosses is therefore `Problem::CrossFlowEdge`, an `Error` in the `DanglingEdge`/`UnknownVar` family of things only a hand-edit or a merge produces — a drag cannot make one, since it needs both ends visible — but moving part of a conversation to another flow does, because splitting a graph is what the move is for. So `Doc::move_to_flow` returns how many edges it cut and the status line says so at once, and the problem row for one selects the edge itself (`Problem::edge`), since neither canvas can be clicked on to reach it; a `DuplicateEdge` row does the same, because the copy lies under its original and `edge_at` finds the original first. `Editor::show` is where the canvas switches, and only there: `jump_to` and `follow` both come through it, so a search hit, a problem row and a play-through that walks into another flow all cross without an arm of their own.

  `remove_flow` is the crate's **third removal policy**, and deliberately neither of the other two: `remove_variable`'s cascade would delete the nodes, and `remove_character`'s undeclare-only would strand them on a canvas nothing lists, so removing a flow *returns its nodes to the main one*. For the same never-strand reason there is no `UnknownFlow` problem — `Doc::all_flows` unions the declared flows with the ones nodes actually stand on, so the tab lists every canvas a node could be on. `flows` exists only so an empty canvas survives a reload and has something to rename; `rename_flow` is the **third find-and-replace** after `rename_variable` and `rename_character`, and a fourth name-keyed field has to join all three.

- **A note is a kind, not a second class of canvas object — and it holds no edges at all.** `NodeKind::Note` is a box the author writes in and the player never sees. A `Doc::notes` vec beside the nodes would have needed its own hit test, its own rung in the mouse map and a fourth `Selection` arm; a kind inherits drag, marquee, group move, search, flows and undo for nothing, which is the same trade a flow makes by being a tab rather than a pane. It is `NODE_W`×`NODE_H` like everything else, because **kinds change what a node draws, never how big it is**.

  **Freestanding is the whole invariant**, and it is stricter than "refuses outgoing edges the way a `Jump` refuses a second one": `add_edge` refuses an edge with a note at *either* end, since an edge *into* one would put a note in `Doc::choices` and offer the player a choice that walks nowhere. That one guard is what buys everything else — a note can never be reached, walked into, or fallen out of, so `pauses_play`, `choices`, `start_walk` and `vars_along` need no arm for it, and `Doc::set_kind` drops every edge touching a node converted to one. It also means the *port is not drawn and not hit* (`port_hit_test` skips a note): a handle that can never land is the same lie an undrawn edge out of a jump would be. In `problems` the three graph rules — `roots`, `Unreachable`, `DeadEnd` — skip notes as a group through one `in_graph` filter; both halves are load-bearing, since counting notes as roots would let a document of nothing but notes suppress `NoStart`, and skipping only roots would report every note unreachable. But `Problem::Empty` **does** fire on a blank note, unlike `Hub` and `Jump`: text is what a note exists to hold, so the rule's own wording catches it. `insert_node` never branches a note off the selection either — it always lands in the middle of the view, because the edge would only be refused.

  It draws in **its own font**, serif and italic, not just its own colour: the bundled UI font has no italic face, so `.italic()` alone renders identically to a line of dialogue, and a note that reads as speech is the one thing this kind must not do. `play_seed` skips a note so F5 with one selected does not start a play-through that immediately reports running out of graph.

  // ponytail: a note's leader arrow — the line pointing at what it annotates — is not built. When it lands it is drawn, never stored: a `Node::pin: Option<NodeId>` painted by `edge_lines`, never an `Edge`, so nothing in `choices`/`start_of`/`advance` learns the word. Keeping notes out of `Doc::edges` is what keeps that door open.

- **An export is not a save, and `Doc::export_ftl` takes `&self` so the compiler says it.** `.ftl` out is the export half of localisation; a translation *view* is still out of scope and this must not grow one. It splits the way JSON IO already does — `to_ftl` is the pure string builder `to_json` is, `export_ftl` the thin `std::fs::write` beside `save` — and takes **no dependency**: writing FTL is `id = value`, while *parsing* it back is the half that would earn `fluent-syntax`. The `&self` is what keeps it from drifting into `save_to`'s shape: an export must not clear `dirty`, drop the crash copy, or become `self.path`, so the editor never ends up pointed at the `.ftl`.

  **The key is the id, never the alias.** An alias is optional, author-renamable and never auto-generated, so a file keyed on one breaks the first time somebody edits it, while an id is random, stable and never reissued. A Fluent identifier cannot start with a digit, hence `node-<id>`; an edge is `edge-<from>-<to>` by its endpoints rather than its index, because `Selection::Edge(usize)` is invalidated by any edge removal and a translation key has to outlive one. **Only what a player reads is translatable** — `Node::player_text`, and a label only on an edge out of a node that has some, so neither an instruction's leftover line nor a condition's leftover choice reaches a translator. A note is the plainest case, since author-facing text must never reach one — and speaker names stay out too, since `Node::speaker` *is* the key `rename_character` finds and replaces and a display name with a space in it is not an identifier. Edges need no note filter of their own: `add_edge` already refuses one at either end.

  Three things `ftl_entry` owes the format. An **empty value will not parse**, so a blank node is skipped rather than written as `node-<id> = ` — the document already says so through `Problem::Empty`. A value ends at the first **unindented** line, so a multi-line one becomes a block value with every line indented, blank lines included. And a brace opens a placeable, so text carrying one is escaped in a **single pass** — chaining two `replace` calls re-escapes the braces the first one inserted, which is what `ftl_escapes_a_brace` is there to catch. `with_default_extension` takes the extension as a parameter for this feature rather than gaining a second copy of the same rule.

- **`sync_fields` runs on every keystroke** (via `cx.observe` on the three `Entity<TextInput>` handles, wired in `Editor::new`), so it must early-return when the content is unchanged — otherwise `set_content` → notify → sync loops and spams checkpoints. It is paired with `load_fields`, which pushes doc content *into* the fields; `self.edited` tracks which selection the fields currently hold. There is no `cx.emit`/`cx.subscribe` anywhere in the crate.
- **`render` sets the window title**, but only when it changed — render runs constantly, so keep any other side effect out of it.
- **Every piece of chrome has one scope and one surface, and the sidebar is the inspector and nothing else.** What is true of the *selection* goes in the inspector (`Editor::inspector`: a header, then ruled `section`s — Type, Content, Logic, Identity — with a document summary as its empty state); of the *document or the view*, in the status bar (problems badge, flow, zoom, status message, file and dirty dot); and anything used in bursts is an **overlay** that is in the tree only while open: find (`searching`, Ctrl+F), the problems drawer (`problems_open`, opened from the badge) and the shortcut sheet (`help_open`, F1). They used to be stacked in the sidebar at the same weight as the fields, which is what made the editor read flat; a new control picks its scope first and the surface follows. The sheet is generated from `MENUS`, so a command added there appears in it with no further work. Three rules keep the overlays honest. **Escape peels one layer**: `on_stop_play` closes whatever overlay is open and *only otherwise* stops the play-through, and `on_focus_canvas` (Escape from a field) closes find — so a script that needs both sends it twice. **An overlay blocks the canvas beneath it** with `.occlude()` *and* a mouse-down `stop_propagation`, the pattern `menu_dropdown` proved; both are needed and a pointer test (`/dev/uinput`, absolute device, geometry found from a full-screen capture) is how this was checked, since a click that also started a marquee under the drawer would be silent. **A status message expires**: `set_status` bumps `status_gen` and a timer clears it only if that generation is still current, so a newer message is not cleared by an older timer.
- **`kind_style` is the one place a node kind's glyph, name and colour live** — the canvas box, the inspector header, the kind picker and the find results all read it, so they cannot disagree. A kind's glyph sits *beside* its content (`glyph_row`), never above it: stacked, it took a whole line of a box that is only `NODE_H` tall.
- **Key contexts nest, and the root owns them**: `"Editor"` on the root `div` in `render`, with every `.on_action` listener; `"Canvas"` on the canvas pane, which holds the focus handle; `"TextInput"` on each field. gpui matches a binding only against the focused element's *ancestors*, and the fields sit beside the canvas rather than inside it — so while `"Editor"` was on the canvas, Ctrl+S, Ctrl+Z, F5 and even Escape did nothing from a field. Bind a command to `"Editor"` unless the key means something else while typing: only `delete`, `backspace` and `tab` are `"Canvas"`. `escape` is in two scopes and the deeper wins — `FocusCanvas` in `TextInput`, `StopPlay` in `Editor` (a no-op when nothing is playing).
- **Node ids are random, not counted.** `Doc::fresh_id` mints one with `RandomState::new().hash_one(..)` — stdlib, OS-seeded, no dependency — retrying on the birthday case. A counter was shared state: two branches that each added a node minted the same id, and git merged that cleanly into a document whose edges pointed at the wrong nodes, the one corruption a `.dln` could suffer in *silence*. That is why there is no `.gitattributes` blocking the auto-merge any more, and why `Problem::DuplicateEdge` exists: a merge can now produce the duplicate `add_edge` refuses. Ids are therefore **stable across a history step** — there is no counter for `restore` to roll back, so an undone id is retired rather than reissued. Old files carrying a `next_id` still load; serde ignoring the unknown field is the whole migration. Two consequences to keep: a 19-digit id is never shown to the author (`node_number` in `main.rs` prints the node's 1-based *position* instead), and **nodes are never sorted by id on write** — paint order is insertion order and `hit_test` reverse-iterates it, so sorting would silently reshuffle z-order on reload.
- **`NodeId` is a type alias, and the reason is auditability.** Widening ids was a sweep over ~70 one-token sites; `main.rs` also holds colours as a plain integer, so a find-and-replace on the bare type would have silently widened one of those. Nothing else is built on the alias and nothing else should be.
- The `.dln` file is pretty-printed serde JSON of `Doc`; `undo` and `dirty` are `#[serde(skip)]`, so loading starts with empty history and clean state. `with_default_extension` only appends `.dln` when the path has *no* extension, so "Save As `scene.json`" stays `.json`.
- A fresh `Editor` starts on `Doc::sample()` (an innkeeper conversation with one of every node kind), not an empty document.

## Conventions

- **Adding a command touches four places**: the `actions!` list, the `MENUS` table, an `.on_action(cx.listener(...))` line on the root `div` in `render`, and `cx.bind_keys` in `main()`. Menu items are `fn` pointers to the same handlers the keybindings call, so every action is reachable both ways. The six Node-menu commands are six actions over one `Editor::insert_node(kind, ..)` — gpui's `actions!` generates unit structs, so a parameterised command has to arrive as one thin handler per value.
- **`insert_node` always creates something, and never on top of something.** With exactly one node selected it branches off it (`Doc::branch_from`); otherwise it drops the node in the middle of the current view via `View::to_doc(pane_center)`, less half a node so it lands centred rather than top-left. Both go through `Doc::free_spot`, which slides the spot down a row at a time past any node on that canvas it would cover — dropped dead on a node, the new one hid it, and a second Ctrl+6 hid the first. Silently refusing when nothing is selected would make a menu item that looks broken. Only a `Speech` node pulls focus into the speaker field afterwards — every other kind is edited with pickers, so the keyboard stays on the canvas.
- Menu dropdowns are `deferred` so they paint above the canvas, and they `stop_propagation` on mouse-down — otherwise the canvas's own mouse-down closes the menu before the item click lands. Drags register `on_mouse_up_out` alongside `on_mouse_up` so a release outside the pane still clears `self.drag`.
- File dialogs (`cx.prompt_for_paths`, `cx.prompt_for_new_path`) are driven with `cx.spawn(...).detach()`; the real return shape is a triple-nested `Ok(Ok(Some(..)))`. A failed load leaves the current document untouched. All IO errors are stringified (`Result<_, String>`) — there is no `anyhow`.
- **The crash copy is one fixed file and `Doc::write_backup` must never become `save`.** A timer in `Editor::new` writes `autosave_path()` (`temp_dir()/palaver-recovery.dln`) every `AUTOSAVE_EVERY` while `is_dirty()`, skipping a tick mid-drag, and stopping for the session after one failure (`autosave_off`) so a read-only temp directory does not report every 30s. `write_backup` deliberately leaves `dirty` set — clearing it would drop the `*` from the title and disarm the close guard — and it writes a `.tmp` then renames, because a kill mid-write is the event the file exists for. The backup holds the origin path beside the document (`Backup`), so recovery restores the file association too; nothing is ever written next to the user's document. `Editor::offer_recovery` runs once from `main()` and only an explicit "Discard" deletes the file — a cancelled prompt resolves to `Err` and must leave it alone.
- **`Editor::replace_doc` is the only way to swap the document**, and the only place `clear_backup()` is called on a swap. `reset` (File→New), the Open success arm, and recovery all go through it, so none of them can forget the backup, the view reset or `select(Selection::None)`. The non-swap clear sites are `save_to` on success, the confirmed branch of `confirm_close`, and — feature-gated — `automation.rs`'s `quit discard`, its non-interactive twin.
- **Anything that discards the document must go through `Editor::confirm_discard` first.** It resolves to `true` on "Discard", and all three paths that replace the document — File→New, File→Open, and the window-close hook — go through it. Any fourth one must too — `automation.rs`'s `open` and `quit` are the non-interactive case, and they *refuse* a dirty document instead of prompting, with `quit discard` as the explicit "Discard". Recovery is the one exemption and pays for it in kind: `offer_recovery` returns without replacing anything if the document went dirty while its prompt was up, because a gpui prompt does not hold the mouse on Linux and the canvas stays clickable underneath. The close path is a two-pass veto: `on_window_should_close` is synchronous but `window.prompt` is not, so the first pass returns `false` and spawns the prompt, "Discard" sets `Editor::closing` and calls `window.remove_window()`, and the second pass returns `true`. `on_window_closed` fires after the fact and cannot veto — it only quits.
- `// ponytail:` comments mark deliberate shortcuts with their ceiling and upgrade path (O(n) node lookup, snapshot undo, sync file IO). Respect the ceiling before optimising; keep the format when adding one.
- GUI code can't be asserted on in `cargo test`. Any new document logic goes in `doc.rs` with a unit test; `main.rs` stays a thin view over it.

## Out of scope

What follows is not deferred work — there is none. It is the list of things deliberately *not* built, kept so nobody half-builds one by accident.

**Templates** — articy:draft's central idea is user-defined property schemas: every entity and node type gets an editable template with its own fields, constraints and read-only properties. Our fixed `Node { speaker, text }` is the opposite of that, and adopting it means a dynamic property bag plus a schema editor — a bigger project than everything above it combined. Named here so nobody half-builds it by accident while adding a field.

**String and float values** — `Value::Str` costs the enum its `Copy`, which ~15 signatures in `doc.rs` lean on, and buys equality that a set of flags already gives; float equality in a dialogue graph (`== 0.3`) is a footgun. Add `Str` if an author ever needs to compare a name. **Expressions** (`gold >= price`, `a + b`) are further out still: every effect and check compares a variable to a *literal*, and an expression language is a parser.

**`NodeKind::Alt`** — ink's sequences, cycles, once-only and shuffles as one kind answering *which of my outgoing edges do I take this time?*, a `Pick { Sequence, Cycle, Once, Shuffle }` with one arm in `walk_on`. Audited and cut, because the four policies do not hold together. `Once` is `Edge::once` again under a second name, and reopens on purpose the one case that toggle deliberately refuses — a once-only edge out of plumbing, where the walk has to take the edge it finds. `Shuffle` is not a function of a visit count like the other three, so it needs an RNG in `doc.rs` and makes `walk_on` unassertable in the crate's only testable layer. `Sequence` and `Cycle` are the pair that pays — the workaround is an `Instruction` plus a `Condition` per branch, four plumbing nodes for a three-line cycle — but their semantics *are* the order of the outgoing edges, which is `doc.edges` insertion order: set by the order the ports were dragged, and reorderable nowhere in the crate. Writing the index into the label slot the way `edge_labels` writes a branch makes a wrong order visible, not fixable. So the honest price is a kind chip, a seventh Ctrl-key, a `node_box` arm, an `Empty` exemption *and* the crate's first list-reordering widget — and `Doc::visits`, which shipped ahead of it, was deleted with it. Take it on only with the reorder widget priced in; seven kinds is also where `kind_picker` wraps and Ctrl+1–6 stops being a mnemonic.

**Inline text markup** — ink's `{A|B|C}` alternatives, its `{cond: a|b}` conditional interpolation and its glue `<>`. All three are a parser living inside `Node::text`, which is **logic as a node property**, the one thing this crate is built not to do. The varying half is `NodeKind::Alt` above. Conditional interpolation is a `Condition` with two `Speech` nodes under it and needs nothing new at all. Glue has nothing to attach to: ink assembles a paragraph out of fragments gathered across diverts, while here one node is one line and there is no assembly stage to glue across. Take any of the three and the text field stops being text.

Also considered and rejected as out of proportion to a local single-file editor: localisation *views* — an in-editor translation column or a language switcher, the export half having shipped — multi-user collaboration and version control, AI and voice synthesis, game-engine import plugins, the vector Location editor, the Word-like Document view, and the plugin/macro SDK.

These stay out. If one is ever taken on, it earns a section above like every shipped feature, not an entry here.
