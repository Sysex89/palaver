# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`papugai` — a node-graph dialog editor in the spirit of articy:draft: branching dialogue graphs of speaker/text nodes connected by labelled choice edges.

Working today: pan and zoom, node drag, edge drag from a port, marquee multi-select and group move, select/delete node or edge, sidebar text editing, search and jump-to-node, a Node menu that quick-creates a connected node of any kind (Tab, Ctrl+1–5), a validation problem list, marking a node as an ending, an alias on any node for a game engine to look it up by, hub, jump, instruction and condition nodes, boolean variables declared, renamed and deleted in their own pane, written by instructions, read by conditions to pick a branch, and watched live in play mode, snapshot undo/redo, new/open/save/save-as of `.dln` JSON files, autosave with crash recovery, and play mode.

The intended end state is bigger than that — see **Roadmap** at the bottom. Everything outside that section describes code that exists; the roadmap is the only forward-looking part of this file.

## Stack

- Rust, edition 2024 (verified on rustc 1.97).
- GUI: **GPUI** (`gpui` 0.2.2), the framework Zed is built on. Its API still moves between releases — the version is pinned, and when an API doesn't match the docs, read the source in `~/.cargo/registry/src/*/gpui-*/` rather than guessing.
- On Linux GPUI renders through Vulkan/Blade and needs X11/Wayland + Vulkan dev packages present; a build failure in `blade-*` or `gpui` almost always means a missing system lib, not a code bug.

## Commands

```sh
cargo run                 # run the app
cargo build --release
cargo test                # all tests (doc.rs only; GUI code is untested by design)
cargo test <name>         # single test by substring, e.g. cargo test undo_restores
cargo test -- --nocapture # see println!/dbg! output
cargo clippy --all-targets -- -D warnings
cargo fmt
```

The tree is clean under both `cargo fmt --check` and clippy at `-D warnings`; keep it that way.

## Layout

Three files, no `lib.rs`:

- `src/doc.rs` — the document model. `Doc { nodes, edges, variables }` plus geometry constants (`NODE_W/H`, `PORT_R`), hit-testing, undo and JSON IO. **Imports no `gpui`** and must stay that way; it is the only testable layer (89 unit tests at the bottom of the file). It also holds `View`, the canvas pan/zoom transform — not document state, and never serialized, but pure arithmetic that belongs where it can be tested.
- `src/main.rs` — `Editor`, the single `Render` view: menu bar, then a row of variables pane, canvas pane and inspector sidebar, plus all mouse/key handling.
- `src/text_input.rs` — a single-line `TextInput`, **vendored from gpui 0.2.2's `examples/input.rs`**; the header comment lists the local deltas. Treat it as third-party: on a gpui upgrade, re-vendor and re-apply the deltas rather than hand-patching. It holds the crate's only hand-written `impl Element` (`TextElement`, `text_input.rs:544`). `text_input::bind_keys(cx)` must be called at startup or the fields ignore every key.

## How the canvas is actually drawn

Hybrid, deliberately:

- Node boxes, port dots and edge labels are **absolutely-positioned `div`s** built in `Editor::canvas_pane`. Follow this when adding chrome — do not port them to a custom element.
- Only the edge lines and arrowheads go through gpui's `canvas()` helper + `PathBuilder` (`src/main.rs:605`), because there is no div-based way to draw a diagonal line.
- Hit-testing is **not** GPUI's; it is arithmetic in `doc.rs` (`hit_test`, `port_hit_test`, `edge_at`, `nodes_in_rect`) run from `Editor::on_mouse_down`. Ports overlap node boxes, so `port_hit_test` must be checked first (`doc.rs:100`). `hit_test` iterates in reverse so the topmost (last-painted) node wins.

### The mouse map

`on_mouse_down` is an ordered if-chain and the order *is* the specification; adding a gesture means picking its rung. Alt is checked before any hit test, so Alt+left pans over anything. Then: out-port → edge drag; node + shift → toggle it in the set, no drag; node already selected → keep the set and drag the group; node → select just it and drag; edge → select it; empty + double-click → create; empty → marquee.

**Middle-drag pans**, via `on_pan_down`, which the Alt+left branch also calls — the two gestures share one function so they cannot drift apart. `on_mouse_move` is button-agnostic, so panning needed nothing there, but every button that can start a drag must register `on_mouse_up` *and* `on_mouse_up_out`.

A plain click on empty canvas is a zero-size marquee that touches nothing, so clearing the selection falls out of the marquee commit in `on_mouse_up` rather than being its own branch.

### Coordinate spaces (the most common source of bugs)

Three of them:

1. **Window** — what mouse events carry.
2. **Canvas pane** — window minus `MENU_H` *and* minus `VARS_W`, since the pane sits under the menu bar and to the right of the variables pane. With `SIDEBAR_W`, those three constants are what bound the pane. Any new chrome to the left of or above the canvas has to be subtracted in `Editor::window_pos` too, or every hit test in the editor is wrong by its width — this is the single most breakable thing in the file.
3. **Document** — `screen = doc * zoom + pan`. Everything in `doc.rs` is in this space.

`View::to_doc`/`to_screen` own step 3; `Editor::window_pos` owns step 2, and `doc_pos`/`screen_pos` compose the two. Go through those helpers, never the raw arithmetic. Separately, inside the `canvas()` paint closure coordinates are window-absolute, so `bounds.origin` is added back.

`pan` is in **screen** pixels, which is why `Drag::Pan` is the same arithmetic at every zoom. Lengths that start in document units (`NODE_W`, `PORT_R`, label widths, font sizes) need `View::scale`. Hit tolerances (`PORT_R`, `EDGE_HIT_TOL`) are deliberately *not* scaled — they live in document space, so targets get smaller on screen as you zoom out.

## Invariants

- **Checkpoint before you mutate.** `Doc` never checkpoints itself — the view calls `doc.checkpoint()` (`doc.rs:154`) *before* each mutation. It pushes a full snapshot (50 deep) *and* sets the dirty flag; it is the single choke point for both, and `dirty` is only cleared in `save()`. A mutation that skips it is both un-undoable and silently unsaved. `Snapshot` is every serialized field of `Doc` — nodes, edges, variables — so a new one has to join it or a whole class of edit quietly stops being undoable; `undo_restores_a_deleted_variable` is the test that catches the omission. `undo()` and `redo()` also set dirty — stepping through history counts as an edit.
- **`checkpoint()` clears the redo stack**, since a fresh edit branches history. `undo`/`redo` are symmetric: pop one stack, push the current snapshot onto the other. Only `undo` is capped at `UNDO_DEPTH`; the redo stack needs no cap of its own because it can only ever hold snapshots `undo` popped.
- **Checkpoints are placed to avoid empty undo steps.** Typing coalesces: `Editor::checkpoint_once` + the `text_dirty` flag give one checkpoint per editing session, and `text_dirty` resets in `load_fields` when the selection changes. Node drag checkpoints on the first `MouseMove`, not on mouse-down, so a plain click leaves no history entry.
- **`Selection` is `None | Nodes(Vec<u32>) | Edge(usize)`** — plural for nodes, singular for edges. `Selection::Edge(usize)` is a bare index into `doc.edges`, invalidated by any edge removal; the mitigation is convention: every structural change calls `select(Selection::None, cx)`, and `after_history` re-validates the node set against the document and drops anything else. Node ids survive a history step, so a node set does not need the same treatment — only the ids that vanished are filtered out.
- **`Selection::only_node()` is the gate on every single-node path** — `load_fields`, `sync_fields`, `on_branch`. A multi-selection returns `None` there, so it has no inspector fields to write and cannot half-edit a group. New per-node commands go through it too, not through `nodes()[0]`.
- **A group drag anchors the grabbed node and moves the rest by its delta** (`Drag::Node` in `on_mouse_move`), rather than storing a per-node offset. That way the node under the cursor never drifts, and the maths is the same for one node as for twenty.
- **A start is relative to the selection, not a property of the document.** `Doc::start_of(id)` walks incoming edges back to a node nothing links to, so a document holds as many independent conversations as the author draws and F5 plays whichever one the selection is standing in (Shift+F5 starts at the selected node itself). This is why `Problem::ManyStarts` was deleted: several roots is now the intended shape. `NoStart` stays, since a document where nothing can begin is still broken. `start_of` guards against cycles with a visited set and returns the node it started from when there is no top to find.
- **Play state is one `Option<Vec<u32>>`** on `Editor` — the path walked so far, current node last, which is all Back (`pop`) and Restart (`truncate(1)`) need. While it is `Some`, `play_panel` *replaces* the inspector arm in `sidebar` so the sidebar is never an editor and a player at once, and `replace_doc` clears it because node ids belong to the document that left. Play follows the canvas with `Editor::show` (centre only) rather than `jump_to`, deliberately: advancing must not rewrite the selection play was started from. The panel guards on `doc.node(current)`, since the node can be deleted from the canvas mid-play.
- **A `Jump`'s target is an ordinary `Edge`.** `NodeKind` is `Speech | Hub | Jump`, and the whole trick of it is that a jump introduces no second kind of link: `choices`, `problems` reachability, `start_of` and `nodes_in_rect` need no jump awareness because the edge is real, and the target is authored by dragging from the out-port like any other. The kind only changes how that edge is *drawn* — `edge_lines` and `edge_labels` both skip an edge leaving a jump (via `Doc::is_jump`, shared so the two cannot drift), and `node_box` names the target instead. A jump has exactly one target: `add_edge` refuses a second, and `kind_picker` drops all but the first outgoing edge when converting a node to one, because an edge that is neither drawn nor reachable would be a lie about the graph.
- **Kinds change what a node draws, never how big it is.** Hit-testing is arithmetic over `NODE_W`/`NODE_H` in `doc.rs`, so a hub drawn smaller than it is clicked would put the two out of step. Every kind keeps the same footprint.
- **`end: bool` stays orthogonal to `NodeKind`, deliberately.** An ending has text — "Farewell, traveller." is a `Speech` node that happens to terminate — so folding `End` into the enum would make "is an ending" and "is dialogue" mutually exclusive. `Problem::Empty` means "holding none of whatever this kind exists to hold" — no dialogue on a `Speech`, no writes on an `Instruction` — so `Hub` and `Jump` are exempt from it for the same reason `end` exempts a node from `DeadEnd`: neither holds anything to begin with. **Only a `Speech` node has a speaker.** A hub's `text` is an optional label for it ("Anything else?"), a jump and an instruction use neither field, and `Node::speaker` never means anything but who is talking — which is what keeps **entities** from having to special-case a kind that nobody speaks at.
- **A `Node::alias` is the only stable handle the format offers the outside world.** `Node::id` is a random `u64` minted per node — unique and stable, but meaningless to a human and unwritable by hand — and a start is derived by `Doc::start_of` rather than stored, so neither is something an author can point a game build at. That sets the alias's two rules: **never auto-generated, never auto-renamed**, because a handle the editor changes is not a handle. Empty is the ordinary state — the field is reachable from every node so that *any* node can be named, not so that every node must be, and a blank alias is never a `Problem`. Orthogonal to `NodeKind` like `end` is, so the inspector field sits outside every kind guard: entering a conversation at a hub or a condition is a legitimate thing for a game to want. Conflicts are caught after the fact, not refused at entry the way a duplicate variable name is — `sync_fields` runs on every keystroke, so typing toward `intro_two` transiently reads `intro` and a gate would refuse the author mid-word. `Problem::DuplicateAlias` is therefore an `Error` raised on *both* offending nodes, and only between two **non-empty** aliases that match: without that skip every un-aliased node in the document would collide with every other.
- **Logic is graph structure, never a node property.** This is articy's model and the reason `NodeKind` keeps growing instead of `Node` growing fields: an `Instruction` is a node you can see, select, move and search, not a hidden panel on a line of dialogue. It is also what keeps the crate clear of **Templates** (see *Out of scope*) — a `Node::effects` bag readable on every kind would be a miniature of exactly that. `effects` is therefore the *content* of an `Instruction`, the way `speaker` is only ever a `Speech` node's: `vars_along` reads effects only from an `Instruction`, and `kind_picker` clears them when converting a node away from one, so the field cannot quietly become a property bag.
- **`Doc::pauses_play` is the one definition of a node the player sees** (`Speech | Hub`; a missing node counts as visible, so a broken graph halts rather than walking off the end). The walk and the panel that renders its result both go through it, so they cannot disagree about which nodes are authoring plumbing. A hub is a branch point, so `play_panel` shows its choices with no dialogue line above them and needs no special case to do it. The walk normally lands on a node this is true of — when it does not, it ran out of graph (a condition with that pin unwired, a jump pointing at nothing), and `play_panel` must say so rather than render a plumbing node as a blank line of dialogue.
- **A condition's true/false pins are a `bool` on the `Edge`, not a second out-port.** `out_port`, `port_hit_test` and the whole mouse map therefore know nothing about the kind, and a branch is authored by dragging from the same single port. `add_edge` gives the *first* edge out of a condition the true branch, since the happy path is what gets drawn first. `Edge::branch` is meaningless from any other kind and left `false` there. The branch is shown two ways so it is never guessed at: the line is drawn in `TRUE_COLOR`/`FALSE_COLOR`, and `edge_labels` writes `true`/`false` in the label slot — which on a condition would otherwise hold text the player can never read, so the edge inspector swaps the Choice field for the branch toggle too.
- **`walk_on` is the only place a condition is ever evaluated**, and `Doc::choices` is never filtered — the editor and the player see the same graph, and the canvas never hides an edge. That is the payoff of logic-as-nodes over guarding edges, which was considered and rejected. The walk recomputes `vars_along(path)` at each condition it meets rather than carrying a `VarState`, which keeps the path the single copy of the play state.
- **`effects` and `conditions` are separate fields with a shared editor.** `Effect { var, value }` and `Condition { var, want }` are structurally identical, and merging them would save a struct — but checks living in a field called `effects` is the `speaker`-as-hub-name mistake again. The duplication that actually mattered was the widget, so `var_rows` takes a `VarRow::Sets | VarRow::Checks` and both kinds share it.
- **The play path holds every node visited, including the ones walked through.** `Doc::start_walk`/`advance`/`step_back` do the walking, and they replaced `resolve_jump` rather than sitting beside it — it was already "walk through what the player never sees", and `Instruction` is just the second such kind. Keeping the invisible nodes in the path is what lets `Doc::vars_along` recompute the variables *from the path alone*: there is no second copy of the state, so Back cannot rewind the node without rewinding the flags. `step_back` searches by position, not by id, because a conversation that returns to a node it has already played would otherwise jump to the wrong occurrence of it. Restart re-walks from `path[0]` rather than truncating, so a conversation opening on an instruction runs it again. The walk guards against a cycle with a visited set, like `start_of`.
- **`Problem` carries no message text.** `Doc::problems` returns an enum; the wording lives in `problem_text` in `main.rs`, which keeps view strings out of the model and lets the tests assert on variants instead of phrasing. Its `Severity` split is load-bearing, not decoration: a leaf node is an ordinary way for a conversation to end, so only a broken document (`DanglingEdge`, `NoStart`) is an `Error`. Anything new that would fire on a healthy graph is a `Warning`. `Node::end` is the opt-out: a node marked as an ending is skipped by the `DeadEnd` rule, so the list only names leaves the author has not vouched for. Keeping the wording in the view also means a variant can read differently per node kind without the model growing a variant for it — `DeadEnd` on a jump is worded "Jump with no target".
- **The four inspector inputs are observed as a group; `search_input` and `var_input` are not.** The `sync_fields` loop in `Editor::new` exists to write field content *into* the selected node — a search query and a not-yet-declared variable name are not that node's content, so they share a second observer that only calls `cx.notify()`. Adding a non-document field to the first loop would write it into the selected node; `alias_input` is in it precisely because an alias *is* node content.
- **A variable is keyed by its name, not by an id** — deliberately unlike the plan for **entities**. The name is what a `.dln` diff and a merge stay readable through, and there are few enough variables that `add_variable` can enforce uniqueness outright. The payoff is that a rename *is* a find-and-replace: `rename_variable` rewrites the declaration, every effect and every check, and there is nowhere else a reference can hide — which makes it, with `remove_variable`, the second function a third name-storing field would have to join. `variable_name_free` exists as a separate public check so the view can refuse an add *before* it checkpoints — a rejected add must not leave an empty undo step, and `checkpoint` also sets `dirty`. **One `.dln` is the project**, so global means document-global: `variables` is a field of `Doc`, declared from exactly one place (the `+` in `vars_pane`), and nothing else in the crate may mint one. `vars_pane` has one text field and two jobs — `Editor::renaming` is which — so a rename needed no fourth `TextInput` to keep out of the `sync_fields` observer group; a stale `renaming` is filtered at render against the document rather than cleared at every site that could invalidate it. `remove_variable` cascades to every effect naming the flag and returns the count, because an effect writing an undeclared variable has no meaning; it is one checkpoint, so one undo brings the variable and all of its effects back together. `Problem::UnknownVar` is an `Error` for the files that got there anyway — hand-edited or hand-merged — which is the same category `DanglingEdge` exists for.
- **The variables list is its own pane on the left, not part of the right sidebar.** The sidebar is the *inspector* — everything in it is scoped to the selection, and play replaces it wholesale. Variables belong to the whole document, so they get their own pane, stay up during play showing live values, and go read-only while it runs. `vars_pane` is also the only place in the crate that may declare a variable.
- **A variable set is a naming convention, not schema.** `doc::split_set` splits a name on its first `.` and `vars_pane` renders a header per group, showing the rest of the name under it — but the whole dotted name is still the key, so uniqueness stays global, a rename is still a find-and-replace over one string, and a `.dln` is byte-identical to what it was before groups existed. That is the entire cost of the feature: display. A document with nothing dotted must look exactly as it did, which is why the `(ungrouped)` header only appears once some *other* variable has a set. The list itself scrolls (`overflow_y_scroll` on an inner `#var-list`, not on the pane, so the heading and the declare field stay pinned), so unlike its sibling panels it has no row cap — headers were about to make one bite twice as fast.
- **`sync_fields` runs on every keystroke** (via `cx.observe` on the three `Entity<TextInput>` handles, wired in `Editor::new`), so it must early-return when the content is unchanged — otherwise `set_content` → notify → sync loops and spams checkpoints. It is paired with `load_fields`, which pushes doc content *into* the fields; `self.edited` tracks which selection the fields currently hold. There is no `cx.emit`/`cx.subscribe` anywhere in the crate.
- **`render` sets the window title**, but only when it changed (`src/main.rs:514`) — render runs constantly, so keep any other side effect out of it.
- **Key contexts partition the keyboard**: `"Editor"` on the canvas pane, `"TextInput"` on the field. `delete`/`backspace` mean "delete node" in one and "delete character" in the other; `escape` is bound in both, but to different actions and never at the same time: `FocusCanvas` in `TextInput` scope, `StopPlay` in `Editor` scope (a no-op when nothing is playing).
- **Node ids are random, not counted.** `Doc::fresh_id` mints one with `RandomState::new().hash_one(..)` — stdlib, OS-seeded, no dependency — retrying on the birthday case. A counter was shared state: two branches that each added a node minted the same id, and git merged that cleanly into a document whose edges pointed at the wrong nodes, the one corruption a `.dln` could suffer in *silence*. That is why there is no `.gitattributes` blocking the auto-merge any more, and why `Problem::DuplicateEdge` exists: a merge can now produce the duplicate `add_edge` refuses. Ids are therefore **stable across a history step** — there is no counter for `restore` to roll back, so an undone id is retired rather than reissued. Old files carrying a `next_id` still load; serde ignoring the unknown field is the whole migration. Two consequences to keep: a 19-digit id is never shown to the author (`node_number` in `main.rs` prints the node's 1-based *position* instead), and **nodes are never sorted by id on write** — paint order is insertion order and `hit_test` reverse-iterates it, so sorting would silently reshuffle z-order on reload.
- **`NodeId` is a type alias, and the reason is auditability.** Widening ids was a sweep over ~70 one-token sites; `main.rs` also holds colours as a plain integer, so a find-and-replace on the bare type would have silently widened one of those. Nothing else is built on the alias and nothing else should be.
- The `.dln` file is pretty-printed serde JSON of `Doc`; `undo` and `dirty` are `#[serde(skip)]`, so loading starts with empty history and clean state. `with_default_extension` only appends `.dln` when the path has *no* extension, so "Save As `scene.json`" stays `.json`.
- A fresh `Editor` starts on `Doc::sample()` (a 5-node innkeeper conversation), not an empty document.

## Conventions

- **Adding a command touches four places**: the `actions!` list, the `MENUS` table, an `.on_action(cx.listener(...))` line in `canvas_pane`, and `cx.bind_keys` in `main()`. Menu items are `fn` pointers to the same handlers the keybindings call, so every action is reachable both ways. The five Node-menu commands are five actions over one `Editor::insert_node(kind, ..)` — gpui's `actions!` generates unit structs, so a parameterised command has to arrive as one thin handler per value.
- **`insert_node` always creates something.** With exactly one node selected it branches off it (`Doc::branch_from`); otherwise it drops the node in the middle of the current view via `View::to_doc(pane_center)`, less half a node so it lands centred rather than top-left. Silently refusing when nothing is selected would make a menu item that looks broken. Only a `Speech` node pulls focus into the speaker field afterwards — every other kind is edited with pickers, so the keyboard stays on the canvas.
- Menu dropdowns are `deferred` so they paint above the canvas, and they `stop_propagation` on mouse-down — otherwise the canvas's own mouse-down closes the menu before the item click lands. Drags register `on_mouse_up_out` alongside `on_mouse_up` so a release outside the pane still clears `self.drag`.
- File dialogs (`cx.prompt_for_paths`, `cx.prompt_for_new_path`) are driven with `cx.spawn(...).detach()`; the real return shape is a triple-nested `Ok(Ok(Some(..)))`. A failed load leaves the current document untouched. All IO errors are stringified (`Result<_, String>`) — there is no `anyhow`.
- **The crash copy is one fixed file and `Doc::write_backup` must never become `save`.** A timer in `Editor::new` writes `autosave_path()` (`temp_dir()/papugai-recovery.dln`) every `AUTOSAVE_EVERY` while `is_dirty()`, skipping a tick mid-drag, and stopping for the session after one failure (`autosave_off`) so a read-only temp directory does not report every 30s. `write_backup` deliberately leaves `dirty` set — clearing it would drop the `*` from the title and disarm the close guard — and it writes a `.tmp` then renames, because a kill mid-write is the event the file exists for. The backup holds the origin path beside the document (`Backup`), so recovery restores the file association too; nothing is ever written next to the user's document. `Editor::offer_recovery` runs once from `main()` and only an explicit "Discard" deletes the file — a cancelled prompt resolves to `Err` and must leave it alone.
- **`Editor::replace_doc` is the only way to swap the document**, and the only place `clear_backup()` is called on a swap. `reset` (File→New), the Open success arm, and recovery all go through it, so none of them can forget the backup, the view reset or `select(Selection::None)`. The two non-swap clear sites are `save_to` on success and the confirmed branch of `confirm_close`.
- **Anything that discards the document must go through `Editor::confirm_discard` first.** It resolves to `true` on "Discard", and all three paths that replace the document — File→New, File→Open, and the window-close hook — go through it. Any fourth one must too. Recovery is the one exemption and pays for it in kind: `offer_recovery` returns without replacing anything if the document went dirty while its prompt was up, because a gpui prompt does not hold the mouse on Linux and the canvas stays clickable underneath. The close path is a two-pass veto: `on_window_should_close` is synchronous but `window.prompt` is not, so the first pass returns `false` and spawns the prompt, "Discard" sets `Editor::closing` and calls `window.remove_window()`, and the second pass returns `true`. `on_window_closed` fires after the fact and cannot veto — it only quits.
- `// ponytail:` comments mark deliberate shortcuts with their ceiling and upgrade path (O(n) node lookup, snapshot undo, sync file IO). Respect the ceiling before optimising; keep the format when adding one.
- GUI code can't be asserted on in `cargo test`. Any new document logic goes in `doc.rs` with a unit test; `main.rs` stays a thin view over it.

## Roadmap — intent, not code

None of this exists yet. Grep before assuming otherwise. Roughly smallest-first; every one of them now costs a schema change.

**Entities** — speakers as first-class records rather than the free-text `Node::speaker` string. An `entities` vec on `Doc` with its own id space; `Node::speaker` becomes an optional id, keeping the string as a fallback for un-migrated files. Watch the name collision with `gpui::Entity<T>` — call the document type `Character` or `Actor`, or `doc.rs` types become unreadable at the `main.rs` call sites. Only `NodeKind::Speech` carries a speaker, so the other kinds need no story here.

**Values beyond `bool`** — `Value` is an enum with one variant, and serde tags it `{"Bool": true}`, so adding `Int(i64)` and a string is a pure addition that leaves every existing `.dln` loading unchanged. What it costs is entirely UI: `var_rows`' three-state click-cycle only works because a bool has three states to cycle, so an int needs an operator picker (`= ≠ < ≤ > ≥`) and a numeric field instead — and that field is a fifth `TextInput` that must stay out of the `sync_fields` observer group.

**Variable sets, for real** — the display half shipped (see *Invariants*): `chapter1.paid` groups under a `chapter1` header today, on nothing but the convention. What is left is making a set a thing the model knows about — a `set` field on `Variable`, uniqueness moving from global to per-set, and a declaration UI that picks a set instead of relying on the author typing a dot. Worth doing only once a document has enough sets that the convention starts being got wrong; until then this buys nothing the header does not.

**Flow fragments** — nested subgraphs, turning a `Doc` into a tree of graphs rather than one flat node list. Deliberately last: it exists to solve "this graph is too big", and *Jump* nodes plus search solve that far more cheaply. Still the largest change when it comes — it touches ids (unique per fragment or globally?), the `Selection` enum, `View` state (one per fragment), and the JSON format. Design it before starting; snapshot undo over the whole tree stays fine.

### Out of scope

**Templates** — articy:draft's central idea is user-defined property schemas: every entity and node type gets an editable template with its own fields, constraints and read-only properties. Our fixed `Node { speaker, text }` is the opposite of that, and adopting it means a dynamic property bag plus a schema editor — a bigger project than this entire roadmap combined. Named here so nobody half-builds it by accident while adding a field.

Also considered and rejected as out of proportion to a local single-file editor: localisation views and translation, multi-user collaboration and version control, AI and voice synthesis, game-engine import plugins, the vector Location editor, the Word-like Document view, and the plugin/macro SDK.

When a roadmap item ships, move its description into the sections above and delete it from here.
